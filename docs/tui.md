# TUI 参考宿主

`wind-tui` 是本仓库内的终端参考宿主。它在一个进程内打开 `Runtime`，把话题、实例树与
事件流渲染成终端界面，并把用户输入、提供商与模型配置写回数据库。

它是用于验证引擎与演示事件消费的二进制 crate，不属于库契约。宿主可以只依赖
`wind-runtime`，也可以用其他前端替换它；`wind-tui` 不加载 mod UI，不实现审批交互，
也不读取 `event_log`。

本文给出启动路径、布局、数据来源、事件归约、交互与配置写入。运行时的组合、宿主要求与
关停顺序见「架构」；事件的形态、保留策略与投递规则见「事件」；只读查询与写入函数见
「存储」。

## 入口

```text
windai/tui/src/main.rs
  → wind_tui::app::run()
  → tokio 多线程运行时
  → AppDirs::resolve()                 WIND_ROOT_DIR，缺省 ~/.windai
  → Runtime::open(RuntimeOptions::new(dirs))
  → Runtime::subscribe()               Opening
  → fetch::load_startup(storage)       提供商、模型、初始选择
  → 备用屏幕、raw mode、鼠标、bracketed paste
  → event_loop
  → Runtime::shutdown()，恢复终端
```

`AppDirs::resolve` 决定数据库、话题工作区、公共技能、mod 与字节码目录，规则与嵌入宿主
相同。二进制名为 `wind-tui`，用 `cargo run -p wind-tui` 启动，需要可交互的终端。打开运行时
失败时进程以退出码 1 结束，并打印错误。

事件循环是 `tokio::select!` 的四个分支：

| 分支 | 来源 | 处理 |
| --- | --- | --- |
| 终端事件 | 独立线程，每 50ms 轮询一次，通道容量 128 | 按键、鼠标、粘贴、尺寸变化 |
| feed 事件 | `Subscription::recv` | 归约到当前会话，或写入缓冲 |
| 装载结果 | 会话装载任务 | 替换会话并按序重放缓冲 |
| tick | 33ms 间隔 | 重试存储错误、重连订阅 |

每个分支处理完事件后，界面为脏时立即重绘；按键与鼠标的反馈不等 tick。

订阅关闭（`recv` 返回 `None`）时，TUI 记录一条本地日志并重新订阅；重连成功后重新装载
当前话题。装载期间到达的话题事件进入容量 4096 的缓冲，装载完成后按到达顺序重放；溢出时
丢弃缓冲并重新装载。

## 布局

```text
┌───────────────────────────────────────────────┬────────────────────────────┐
│                                               │ Layer 1 mods               │
│                                               │                            │
│                                               ├────────────────────────────┤
│                Content Area                   │ Layer 2 tree               │
│                                               │                            │
│                                               ├────────────────────────────┤
│                                               │ Layer 3 log                │
├───────────────────────────────────────────────┤                            │
│ status bar                                    │                            │
├───────────────────────────────────────────────┤                            │
│ input                                         │                            │
└───────────────────────────────────────────────┴────────────────────────────┘
```

| 区域 | 内容 |
| --- | --- |
| `Content Area` | 当前话题主实例的消息与块，块按 `seq` 升序 |
| `Layer 1 mods` | 话题启用的 mod，每项 `name vN` |
| `Layer 2 tree` | 话题的全部 agent 节点：缩进、`#id`、角色、相位；挂起时带 `wait #<id>` |
| `Layer 3 log` | 事件日志：时刻、事件名、`seq` 与一行摘要；本地消息的来源名为 `wind-tui` |
| status bar | 提供商、模型、思考档位、话题工作区（缺失或空会话时用根目录）、启动目录的 git 分支、用量、主实例相位 |
| input | 多行文本输入；以 `/` 开头时进入命令补全 |

文本块按 Markdown 渲染，推理块以暗色纯文本显示，工具调用显示名称与首行参数，工具结果按
JSON 语法着色。文本渲染结果按 `revision` 与可用宽度缓存，重绘不重复解析。

尺寸规则：

| 条件 | 结果 |
| --- | --- |
| 终端宽 < 72 或高 < 20 | 隐藏右栏 |
| 右栏宽度 | 终端宽度的 2/5，限定 30 到 64 列，且给左栏留至少 40 列 |
| 输入框高度 | 终端高度的 20%，限定 3 到 6 行 |
| 终端高 < 10 | 只显示输入框 |
| 终端高 < 22 | 状态栏只占一行 |

右栏按终端高度分段：mods 取 1/4（3 到 10 行），tree 取 1/3（4 到 14 行），log 占剩余
高度。状态栏内容一行放不下时，只有终端高 ≥ 22 且存在提供商或模型段才折成两行；第一行
优先保留提供商与模型，第二行的尾部段按宽度依次舍弃。

## 数据来源

TUI 只通过 `Runtime::storage()` 与 `Runtime::subscribe()` 取数，不直接访问数据库文件。

| 阶段 | 查询 | 用途 |
| --- | --- | --- |
| 启动 | `list_providers`、`list_models(None)`、`list_topics` | 初始选择：最近话题的模型；否则首个提供商的第一个模型 |
| 会话 | `get_topic_by_id`、`list_instances_by_topic`、`enabled_mods` | 话题、节点树与启用集合 |
| 内容 | `list_instance_context(main)` | 主实例的全部历史块；用量按消息各计一次 |
| 配置 | `list_providers`、`list_models(provider_id)` | 提供商与模型覆盖层 |

历史块在装载后一律标记为已提交；只有订阅事件携带的块会经历流式累加。装载失败时内容区
显示错误文本，下一次 tick 会重试；重试前不清空已有会话。

## 事件归约

只有作用域为 `Scope::Global` 或话题 id 等于当前会话的事件会被处理。全局事件总是写入
日志；其他话题的事件被忽略。装载期间的事件先入缓冲，装载结束后按到达顺序重放。

| 事件 | 动作 |
| --- | --- |
| `core/block.delta` | 按 `message_id` 与 `seq` 定位块：`revision` 更大时把片段并入，未出现时按序插入；已提交块忽略后续增量 |
| `core/block.committed`（`block` 有值） | 以完整块插入或替换同 `seq` 块，标记为已提交 |
| `core/block.committed`（`block` 为空） | 把流式块标记为已提交 |
| `core/message.seal` | 记录结束原因并累加用量；从历史装载的消息不重复累加 |
| `core/message.interrupted` | 记录 `failed`、`cancelled` 或 `aborted` |
| `core/agent.spawn` | 新增或更新节点；节点 id 等于主实例 id 时为 `main` 角色 |
| `core/agent.status` | 更新相位、挂起等待 id 与失败原因；主实例转入终态且没有已定稿消息时，把最后一条未定稿消息标为该相位 |
| `core/agent.sealed` | 标记主实例节点已交付静止 |
| `core/mod.installed` / `updated` / `deleted` | 重新读取话题的启用 mod |

块增量只追加到本地视图，不写数据库。工具调用参数按片段拼接；文本、推理与音频按增量
追加，其他块类型整体替换。

日志是容量 2000 的环形缓冲，每条事件占三行（标题、摘要、空行）。摘要是按事件名解码载荷
得到的一行文本；没有对应摘要规则或载荷无法解码时显示 `-`。每条日志同时保留事件原文，
本地消息除外。会话归约遇到无法解码的话题事件时另行写入一条本地消息。

## 交互

焦点顺序为 `input` → `Content Area` → `Layer 1 mods` → `Layer 2 tree` → `Layer 3 log`；
`Tab` 前进，`Shift+Tab` 后退，面板内 `Esc` 返回输入框。可打印字符、`Backspace` 与
`Delete` 不要求先聚焦输入框：它们把焦点移回输入框再写入。表单打开时它们写入当前字段。
输入框与表单的文本字段把终端光标停在插入点，焦点不在那里时隐藏。

| 按键 | 作用 |
| --- | --- |
| `Enter` | 提交输入；表单中保存 |
| `Alt+Enter` | 输入框中插入换行 |
| `Tab` | 命令补全打开时应用候选，否则切换焦点 |
| `Ctrl+C` | 退出应用 |
| `Up` / `Down` / `PgUp` / `PgDn` / `Home` / `End` | 滚动聚焦面板；覆盖层中移动选择或滚动事件详情 |
| 鼠标滚轮 | 滚动指针所在面板；事件详情打开时滚动详情 |
| 鼠标左键 | 聚焦面板；点击状态栏的提供商或模型段打开对应覆盖层；点击日志标题行打开事件详情 |
| 鼠标拖选 | 选中面板文本并写入系统剪贴板（OSC 52），输入框标题显示复制的字符数 |
| `Esc` | 关闭覆盖层或表单；面板中返回输入框 |

事件详情弹窗展示该事件的完整结构：事件键、信封（时刻、名称、作用域、来源、载荷、形态）
与投递目标。内容按 JSON 语法着色，长行折行，`Esc` 或 `Enter` 关闭。

输入以 `/` 开头且不含空白时，命令候选按前缀匹配。补全中 `Up` / `Down` 选择，`Tab`
应用；`Enter` 在输入不是完整命令名时应用候选，否则提交。

命令：

| 命令 | 作用 |
| --- | --- |
| `/new` | 回到空会话；不创建话题 |
| `/resume` | 列出全部话题及其相位、创建时刻 |
| `/providers` | 选择提供商 |
| `/models` | 选择当前提供商的模型 |
| `/config` | 打开配置覆盖层 |
| `/cancel` | 取消当前话题的主实例 |
| `/help` | 显示命令与按键 |
| `/quit` | 退出应用 |

空会话中提交文本会创建话题：标签取输入的第一行，模型取当前选择。已有会话中提交文本会
调用 `Runtime::submit` 并把受理返回的实例记为主实例。输入内容只作为文本块提交；文件与
图片附件没有入口。有会话时，选择提供商或模型后会调用 `update_topic_model`，把当前话题
切换到该模型。

`/resume` 只切换会话，不答复外部等待。挂起实例在树中显示 `wait #<id>`，答复仍由宿主
调用 `Runtime::resume` 完成。

## 配置写入

配置覆盖层与表单直接写 `Storage`，不经过运行时事件：

| 操作 | 写入 |
| --- | --- |
| 选择提供商 / 模型 | 当前话题的 `topics.model_id` |
| 修改思考档位 | `models.config.reasoning_effort`，取值 `low`、`medium`、`high`、`max` 与当前值 |
| 切换流式 | `models.config.stream` |
| 新建提供商 | 一笔事务：`create_provider`，填写密钥时再 `create_credential` |
| 编辑提供商 | 一笔事务：`update_provider`，填写密钥时再 `replace_credential` |
| 新建模型 | `create_model` |
| 编辑模型 | `update_model` |
| 切换右侧栏 | 只改内存，不落库 |

提供商表单的字段是名称、`base_url` 与密钥：名称必填且唯一，`base_url` 必须是
`http://` 或 `https://` 开头，密钥留空表示不新建或不替换。编辑时表单不回填密钥；填入新值
会替换活动凭据。

模型表单的字段是提供商、名称、适配器、端点与配置：名称必填且在同一提供商内唯一，适配器
取 `openai_completion` 或 `openai_response`，端点留空表示使用适配器默认值且非空时必须
以 `http://` 或 `https://` 开头，配置必须是 JSON 对象或留空。

表单内 `Tab` / `Down` 跳到下一字段，`Up` 回到上一字段；提供商与适配器字段用
`Left` / `Right` 轮换取值，其他字段用 `Left` / `Right` 移动光标。`Home`、`End`、
`Backspace`、`Delete` 与可打印字符与该语义一致。校验失败时焦点跳到出错字段并显示原因；
保存成功后重新读取提供商与模型，并同步当前话题的模型。

## 边界

| 项 | 现状 |
| --- | --- |
| 外部等待 | 只展示挂起与等待 id；没有审批界面，不调用 `Runtime::resume` |
| Mod 生命周期 | 没有安装、更新、删除、启用或停用的入口；只展示当前启用集合 |
| 事件历史 | 不读 `event_log`；内容来自保留窗口回放与 `block` 表 |
| 子实例内容 | 内容区只装载主实例；子实例只出现在树中，其消息不单独展示 |
| 媒体块 | 图片、文件与音频显示类型与字节数，不内联渲染 |
| 工具结果 | 按 JSON 语法着色，最多渲染 60 行，超出以省略号收尾 |
| 输入 | 只提交文本；没有附件、粘贴文件或多模态输入 |
| 分页 | 会话装载读取主实例的全部块，没有增量分页 |
| 日志容量 | 2000 条环形缓冲；更早的事件不再显示 |
| Mod UI | 不加载 `ui/index.js`，也不解析 `windai://` 地址 |
| 多会话 | 同一时刻只显示一个话题；切换会重新装载 |
