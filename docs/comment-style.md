# 注释规范

本文件规定 `windai/*/src` 下代码注释的写法。写注释之前先读它，改完用文末的命令自检。

## 一条判据

**删掉这条注释，读者会不会读错这段代码？**

不会，就删。会，才写，而且只写那一条信息。名字、类型、函数体已经说清楚的事，不重复。

## 保留的四类

### 一、crate 头

`//!` 标题，加「一次调用：」引导的阶段表、流程图，加运行环境事实。例如
`windai/scripts/src/lib.rs`（`wind-scripts` 尚未实现）：

````rust
//! QuickJS 上的 mod 宿主
//!
//! 一次调用：
//!
//! ```text
//! 建运行时      每次调用新建，结束即销毁
//! 装 ctx        按声明与调用模式裁剪，未声明的属性不存在
//! 建加载器      相对说明符解析进该版本目录，模块取自安装期编译的字节码
//! 调处理函数    清单指认的那个导出
//! 读返回值      转成改写后的载荷，或什么都不返回
//! ```
//!
//! 解释器跑在自己的标准线程上，不在任何 tokio 运行时里
````

模块级 `//!` 只在能写成流程图或阶段表时保留。散文式的模块说明删除。

### 二、量

单位、取值范围、数量关系。两个量有关系就写成等式，不写「因为……所以……」。

```rust
/// 产生时刻，epoch 毫秒
pub time: i64,

/// 总内存 = 解释器线程数 × 64 MB
const INTERPRETER_MEMORY_BYTES: usize = 64 * 1024 * 1024;
```

```rust
// 预算 = min(剩余总预算, 订阅声明的预算)
let budget = cx.remaining().min(sub.timeout());
```

### 三、领域语义

名字表达不出来的那层含义，压成名词短语，不超过二十字。

```rust
/// 需要外部输入，调用挂起
Suspended { calls: Vec<String> },
```

```rust
/// 一次 request 调用的默认时间上限
const DEFAULT_TIMEOUT_MS: u64 = 30_000;

/// worker 不响应取消时的回收宽限期
const JOB_GRACE: Duration = Duration::from_secs(10);
```

### 四、`// SAFETY:`

只写条件本身，不写这个条件为什么成立。

```rust
// SAFETY: 字节码必须由本引擎产出，由调用方保证
```

## 删掉的

- 函数 doc：做什么、返回什么、失败怎么归类、参数含义
- 字段 doc：除单位与取值范围外
- 锁序、不变量、调用约定
- 设计理由、后果推演、为什么这样更好
- 步骤罗列、机制复述
- 散文式的模块说明

三个真实的反面样本，原样留在这里给后来者对照：

```rust
// 删：把函数做什么、返回什么、失败怎么归类讲了一遍
/// 在解释器线程上完成一次调用
///
/// 返回处理函数的结果；任何一步失败都转成一句可读的原因，由调用方决定算谁的失败
```

```rust
// 删：if 和 return 已经写明条件与结果，后面半句是推演
// 时钟已经越过期限就记超时而不是成功，否则反复死循环的 mod 每次都把连续
// 超时计数清掉，熔断永远到不了阈值
if Instant::now() >= deadline {
    return JobOutcome::TimedOut;
}
```

```rust
// 删：前一句复述策略，后一句为策略辩护
/// 按规范化名字取模块
///
/// 有字节码就用字节码，读不出来就改读源码并现场编译。这只会让这次调用变慢，
/// 不该让它失败
```

## 断言消息

`.expect(..)`、`.expect_err(..)`、`debug_assert!`、`panic!`、`unreachable!`、`todo!` 的消息
一律英文：小写开头、动词短语、句末不加标点。

```rust
.expect("serialize the tool")
.expect("lock the state")
panic!("expected an event frame, got {other:?}")
```

`assert!` 与 `assert_eq!` 的消息保持英文，它是给人读的失败报告。

## 用词

**用代码里的名字。** 不为已经有的概念另造动词：不写落盘、落库、回落、线格式，写
「写回状态」「写入数据库」「改读源码」「序列化结果」。

**类型名不译。** `Deployment` 是一份已安装版本的运行材料，译作「部署」会读成发布动作。
指类型时写 `Deployment`，指语义时写「已安装版本」。

**不用指示词指代。** 不写「这一份」「那一格」「这一支」，直接点名对象。

## 边界

**只删不写。** 删除一条注释时不要顺手把它的意思改写成表格或短文。拿不准就整条删掉，不要留半句。

**变体 doc 看名字够不够。** `Capability::Http` 不留「出网」，因为名字已经是这个意思。

**测试代码不动。** `#[cfg(test)]` 模块与 `*/tests/` 不在本规范范围内。

**派生 `JsonSchema` 的类型，doc 不能删。** 字段 doc 会进入生成的 schema，删掉会改变
`docs/` 下的契约输出。`ai/src/schema/` 的 OpenAI 官方描述、`eventsource` 的 ABNF 与
SSE 步骤同样原样保留。

**密度。** 一个 crate 的注释通常只有几十条。某个文件里每三个函数就有一条注释，多半是写多了。

## 自检

```bash
cargo fmt --check
cargo check --workspace --all-targets
```

改完顺手看一眼 `git diff --stat`：注释改动应当以删除行数为主。如果新增行比删除多，
说明又写回去了。
