# UI 组件的打包与加载约定

本文规定 UI 组件的**产物形状**：入口在哪个路径、以什么模块格式打包、基础模块从哪里来、
能力从哪个注入点取、由谁挂载。

组件包的其它固定项（清单名、宿主侧入口、skill 与 MCP 资产的目录）见设计正文的「固定项」
一表；本文只覆盖前端那一条。

---

## 一、范围

本文管的是组件**产物**的形状，不管组件的能力。

| 问题 | 由谁回答 |
| --- | --- |
| 组件的入口在哪、怎么打包、谁来加载与挂载 | 本文 |
| 组件能访问哪些能力、未声明的能力怎么收口 | `docs/facade.d.ts` 的「前端门面」 |
| 组件订阅的通道有哪些投递语义 | 同上，以及 `docs/events.md` 的「订阅握手」 |

---

## 二、入口

**入口是 `ui/index.js`，路径相对包根目录。**

**它不是 `index.html`。** 底座加载的是一个模块，挂载由底座负责；组件不创建文档，也不
接管页面。

`ui/` 是**目录约定**，不在清单里声明——与 `scripts/`、`skills/`、`mcp/` 同理。入口地址
不在清单里，由宿主在包落地后算出，随 `core/mod.installed` 与 `core/mod.updated` 的
`ui_entry` 交给前端；包内没有 `ui/` 时该字段不出现。底座据此定位组件模块。

---

## 三、模块格式

**产物以 CommonJS 形态打包。**

底座在加载组件包时注入 `require`，并把组件源码里的 `import` 解析成 `require` 调用。
因此组件源码可以用 ESM 写，产物不必是 ESM。

加载器的形状参考见 `arch2.md` 的 dsh 前端插件系统一节。

---

## 四、基础模块

底座经 `getStaticModules()` 提供四个基础模块：

| 说明符 | 提供的是 |
| --- | --- |
| `react` | 底座的那一份 React 实例 |
| `react/jsx-runtime` | 同一份 |
| `react-dom` | 同一份 |
| `react-dom/client` | 同一份 |

组件使用这些模块时得到的是**底座那一份实例**，不是包内自带的一份。**两棵 React 并存在
同一个页面里会让 hooks 报错**，因此重复打包不是冗余问题，是错误。

**可操作的判据**：产物的 `require` 调用里**不得出现**这四个说明符的本地实现。它们必须
是外部依赖——把 `react`、`react-dom`、`react/jsx-runtime`、`react-dom/client` 一并打进
产物，就是这一条被违反。

---

## 五、注入点

底座把 `UiCtx` 实例注入组件的全局变量 **`window.__ui__`**。组件从这里取 `UiCtx`。

**该绑定是约定，不承担能力授予职责。** 改动它不会让组件多拿或少拿一分能力；真正的收口
是 `host` 上未声明的成员不存在——见 `docs/facade.d.ts` 的「前端门面」。

---

## 六、挂载点

组件可以声明一个固定的挂载点。**声明写在哪里由脚手架定，本轮尚未定下来**：清单里没有这个
字段，清单也刻意不含前端约定（入口、挂载点一类都归构建约定），因此**没有可查的字段名**，
写脚手架时按本约定自定即可。

未声明挂载点的组件，由底座用一个 `position: fixed` 的容器承载，在界面的初始位置渲染。

---

## 自检清单

脚手架作者逐条跑：

1. 入口是 `ui/index.js`，产物不含 `index.html`
2. 产物是 CommonJS，其中的 react 家族全部是外部依赖
3. 组件从 `window.__ui__` 取 `UiCtx`，不从模块级变量缓存它
4. 组件卸载时调用 `subscribe` 返回的那个函数
5. 面板数据一律用 `stateful` 通道，不用 `notice`

**第 3 条与第 5 条各对应一处真实的失败形态。** 前者是模块级变量在两次挂载之间带着上一次
的作用域；后者是"用户新开一个页面时面板是空的"——`notice` 只推给订阅建立时在线的订阅方，
不出基线，晚挂载的组件没有可补的终值。
